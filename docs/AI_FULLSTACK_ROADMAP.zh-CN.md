# AI 全栈实践路线与工作量评估

## 评估口径

以下范围按一名熟悉 Go、Web 和模型 API 的工程师估算，包含实现、自动测试、文档和一次验收修正，不包含外部账号审批、Steam Provider 不稳定造成的等待以及大规模视觉重做。

人日是规划单位，不等于自然日。AI 可以缩短编码时间，但不能省略安全、评测和上线验证。

## 当前完成度

已经完成的 Web 基础里程碑包括：

- 保留原有 CLI 和确定性计算领域层；
- 新增独立 Web 服务二进制；
- 新增健康、商品查询、正向计算、反向计算和历史记录 JSON API；
- 新增同源响应式浏览器工作台；
- 计算成功后通过服务端 CSV 存储持久化；
- API 输入大小限制、未知字段拒绝、方法限制和基础安全响应头；
- API、存储和静态页面的自动测试；
- 本地构建、CI 和运行文档。

这一阶段相当于约 **3–5 人日** 的常规工程工作，目前已经完成。

AI 策略助手 MVP 也已经完成第一条可运行纵向链路：

- 可注入的模型 Provider 接口、默认关闭降级和 OpenAI Responses API 适配器；
- `lookup_items`、`calculate_profit`、`solve_target` 三个严格只读工具；
- 有轮数、消息长度和请求超时边界的模型/工具编排；
- 助手状态与 SSE 事件接口，以及响应式浏览器对话面板；
- 工具依据编号、引用检查和“模型数字必须存在于工具输出”的数值门禁；
- Prompt 版本、模型、耗时、Token、工具次数和失败事件可观测；
- 50 条无需真实模型或网络的固定工具评测场景；
- AI 不可用、工具错误或 Provider 失败时不影响现有 Web 与 CLI。

这一部分约等于 **4–6 人日** 的常规工程工作，并已在后续质量里程碑中补上有限多轮、Provider 原生流解析、停止和重试。

数据层升级里程碑已经完成本地实现：

- Web 默认仓储从 CSV 升级为带版本迁移的 SQLite；
- 记录获得稳定 ID、UTC 创建时间、来源以及未来归属/会话预留字段；
- 金额和比例按现有确定性精度以缩放整数落库，仓储不重复计算公式；
- 批量写入与 CSV 导入均为事务操作，错误不会留下部分记录；
- 历史 API 与页面支持商品前缀、收益结果、稳定顺序和分页；
- 现有 CLI/CSV 契约保持不变，Web 仍可选择 CSV 回滚模式；
- 兼容 CSV 可显式、幂等地导入 SQLite，源文件不会被改写。

这一阶段约等于 **2–3 人日** 的常规工程工作。SQLite 解决了本地单进程的持久化基础，但还不是多用户托管数据库，也未加入备份自动化。

浏览器 E2E 与可部署演示里程碑也已完成本地实现：

- 12 条由确定性计算引擎生成的固定种子记录，通过正式 CSV 导入路径幂等落库；
- 最初 4 条 Playwright Chromium 用例覆盖计算持久化、筛选分页、错误无副作用和 AI 关闭降级；
- 非 root 多阶段容器、只读 Compose 运行时、SQLite 命名卷、健康检查和优雅停止；
- CI 增加真实浏览器门禁与容器重启持久化冒烟；
- 每个请求获得随机关联 ID，结构化日志不记录查询、请求体、Prompt、回答或数据值；
- 新增进程内请求/助手聚合指标，以及能检查当前仓储依赖的健康接口；
- 补充 3–5 分钟演示、备份、恢复和回滚手册。

这一阶段约等于 **2–3 人日** 的常规工程工作。默认 E2E 不访问 Steam 或 OpenAI；本地环境没有 Docker 运行时，因此镜像构建与重启验收由 CI 执行。

AI 质量与可持续对话里程碑已经完成本地实现：

- OpenAI 适配器按官方类型化 SSE 契约解析文本增量、函数参数增量、完成和失败事件；
- 完整回答先经过当前轮工具依据与数字门禁，验证后才按 Provider 原始增量边界发送，未验证原文不会短暂展示；
- HTTP 契约兼容原 `message` 字段，并新增最多 6 条、总长有界、仅页面内存在的临时上下文；
- 浏览器增加停止和显式重试，不在后台自动重复产生模型成本；
- 固定工具基线从 30 条扩展为 50 条，新增 12 条版本化语义套件；
- 新增可选真实模型命令，可比较当前/基线 Prompt，并输出不含 Prompt 原文和工具值的 JSON 报告；
- 报告覆盖工具选择、溯源、延迟、Token、失败分类和调用者费率驱动的成本阈值；
- Chromium 用例扩展到 6 条，新增临时上下文/重试与取消无副作用回归。

这一阶段约等于 **3–5 人日** 的常规工程工作。本地当前没有临时模型密钥，因此真实 Provider 报告命令已经过脚本模型和失败路径验证，但本次没有产生付费真实模型基线；发布说明会明确这一点。

受控托管演示与最小安全边界里程碑正在实施：

- 新增可选共享演示凭据，保护浏览器、静态资源和应用 API，同时保留公开的依赖健康检查；
- 新增有界的每客户端 API 固定窗口限流，以及整个进程每小时的实际模型调用配额；
- 无效输入、AI 未启用等未启动 Provider 的请求不消耗模型配额，已启动、失败或取消的模型工作会消耗；
- 未授权、限流和模型配额拒绝只进入不含凭据、IP 或业务内容的聚合指标；
- Chromium 用例扩展到 7 条，新增受保护页面、公开健康检查和错误凭据回归；
- 新增只能手动触发的真实模型当前/基线工作流，以及每 6 小时可运行的线上只读合成检查；
- 新增平台无关的 HTTPS、Secret、单副本 SQLite、持久卷、备份、恢复和固定 Tag 回滚契约，并在用户确认后选择 Railway、补充配置清单与平台端口适配。

本地实现约等于 **1.5–2.5 人日** 的常规工程工作，当前已经完成并选择 Railway。本里程碑仍缺实际 Railway 项目、持久卷、HTTPS 域名、线上 smoke 与恢复演练；本地也没有临时模型密钥，因此不能声称已有线上地址或付费真实模型基线。完成这些外部验收通常还需 **0.5–1.5 人日**，不含账号审批和平台等待。

## 总量判断

- **可展示的 AI 全栈 MVP：约 0.5–1.5 人日剩余**。本地浏览器、模型工具、确定性领域层、SQLite、AI 质量报告、E2E、容器、基础指标和最小演示安全边界已经闭环，主要缺口是选定平台、实际部署并恢复演练，以及在提供临时密钥后生成一组真实模型对比基线。
- **可公开运营的小型版本：约 16–27 人日剩余**。仍需要托管数据库、身份与数据隔离、完整限流、持久化可观测性、自动备份和发布治理。
- 单人实施时，作品集 MVP 的代码工作通常还需要约 1–2 个工作日；实际日历时间取决于托管账号、持久卷和临时模型密钥。公开运营版本通常仍需约 3–6 周。多人并行不会按人数线性缩短，因为数据契约、评测和上线验收存在依赖关系。

## 推荐下一步

当前“受控托管演示与最小安全边界”变更的下一步是：

1. 创建 Railway 项目并确认实际套餐与 Volume 费用；
2. 使用仓库清单实际验证 TLS、Secret、健康检查、单副本和固定 Tag 回滚；
3. 运行一次线上只读合成检查与新卷恢复演练；
4. 在提供临时真实模型密钥后，手动运行当前/基线 Prompt 的小规模报告；
5. 完成 `v0.6.0` 固定 Tag 和 Pre-release；
6. 再根据多实例和正式用户隔离需求决定是否升级 PostgreSQL。

这一阶段完成后，项目将从“本地质量可衡量的作品集 MVP”升级为“可受控访问和复现的在线演示”。
