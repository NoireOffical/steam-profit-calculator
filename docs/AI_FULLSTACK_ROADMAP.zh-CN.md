# AI 全栈实践路线与工作量评估

## 评估口径

以下范围按一名熟悉 Go、Web 和模型 API 的工程师估算，包含实现、自动测试、文档和一次验收修正，不包含外部账号审批、Steam Provider 不稳定造成的等待以及大规模视觉重做。

人日是规划单位，不等于自然日。AI 可以缩短编码时间，但不能省略安全、评测和上线验证。

## 当前完成度

已经完成的 Web 基础里程碑包括：

- 保留原有 CLI 和确定性计算领域层；
- 新增独立 Web 服务二进制；
- 新增健康、商品查询、正向计算、反向计算和历史记录 JSON API；
- 新增同源响应式浏览器工作台；
- 计算成功后通过服务端 CSV 存储持久化；
- API 输入大小限制、未知字段拒绝、方法限制和基础安全响应头；
- API、存储和静态页面的自动测试；
- 本地构建、CI 和运行文档。

这一阶段相当于约 **3–5 人日** 的常规工程工作，目前已经完成。

AI 策略助手 MVP 也已经完成第一条可运行纵向链路：

- 可注入的模型 Provider 接口、默认关闭降级和 OpenAI Responses API 适配器；
- `lookup_items`、`calculate_profit`、`solve_target` 三个严格只读工具；
- 有轮数、消息长度和请求超时边界的模型/工具编排；
- 助手状态与 SSE 事件接口，以及响应式浏览器对话面板；
- 工具依据编号、引用检查和“模型数字必须存在于工具输出”的数值门禁；
- Prompt 版本、模型、耗时、Token、工具次数和失败事件可观测；
- 30 条无需真实模型或网络的固定工具评测场景；
- AI 不可用、工具错误或 Provider 失败时不影响现有 Web 与 CLI。

这一部分约等于 **4–6 人日** 的常规工程工作。目前仍是单轮、无状态会话；SSE 会即时发送工具进度，再把完整模型回答分块发送，并非 Provider 原生 token 流。

数据层升级里程碑已经完成本地实现：

- Web 默认仓储从 CSV 升级为带版本迁移的 SQLite；
- 记录获得稳定 ID、UTC 创建时间、来源以及未来归属/会话预留字段；
- 金额和比例按现有确定性精度以缩放整数落库，仓储不重复计算公式；
- 批量写入与 CSV 导入均为事务操作，错误不会留下部分记录；
- 历史 API 与页面支持商品前缀、收益结果、稳定顺序和分页；
- 现有 CLI/CSV 契约保持不变，Web 仍可选择 CSV 回滚模式；
- 兼容 CSV 可显式、幂等地导入 SQLite，源文件不会被改写。

这一阶段约等于 **2–3 人日** 的常规工程工作。SQLite 解决了本地单进程的持久化基础，但还不是多用户托管数据库，也未加入备份自动化。

## 总量判断

- **可展示的 AI 全栈 MVP：约 6–10 人日剩余**。核心模型工具调用和本地数据层已经具备，主要缺口是真实模型评测、端到端演示、部署和基础运行监控。
- **可公开运营的小型版本：约 20–34 人日剩余**。需要托管数据库、身份与数据隔离、完整限流、可观测性、备份和发布治理。
- 单人实施时，MVP 通常还需要约 1.5–2.5 周；公开运营版本通常还需要约 4–7 周。多人并行不会按人数线性缩短，因为数据契约、评测和上线验收存在依赖关系。

## 推荐下一步

下一项变更建议实施“浏览器 E2E 与可部署演示”：

1. 增加浏览器 E2E，覆盖计算落库、筛选分页、助手禁用降级与错误状态；
2. 准备稳定种子数据和一条 3–5 分钟演示脚本；
3. 增加容器构建与本地编排，明确 SQLite 文件挂载、健康检查和回滚；
4. 接入基础请求/模型指标与结构化错误日志；
5. 使用临时真实模型密钥执行 smoke/eval，验证固定基线之外的语义工具选择；
6. 再根据部署目标决定升级 PostgreSQL，或先保留单实例 SQLite 演示。

这一阶段完成后，项目将形成从浏览器、模型工具、确定性领域层到持久化和可重复部署的完整作品闭环。
