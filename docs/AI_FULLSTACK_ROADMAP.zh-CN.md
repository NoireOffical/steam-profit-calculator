# AI 全栈实践路线与工作量评估

## 评估口径

以下范围按一名熟悉 Go、Web 和模型 API 的工程师估算，包含实现、自动测试、文档和一次验收修正，不包含外部账号审批、Steam Provider 不稳定造成的等待以及大规模视觉重做。

人日是规划单位，不等于自然日。AI 可以缩短编码时间，但不能省略安全、评测和上线验证。

## 当前完成度

已经完成的 Web 基础里程碑包括：

- 保留原有 CLI 和确定性计算领域层；
- 新增独立 Web 服务二进制；
- 新增健康、商品查询、正向计算、反向计算和历史记录 JSON API；
- 新增同源响应式浏览器工作台；
- 计算成功后通过服务端 CSV 存储持久化；
- API 输入大小限制、未知字段拒绝、方法限制和基础安全响应头；
- API、存储和静态页面的自动测试；
- 本地构建、CI 和运行文档。

这一阶段相当于约 **3–5 人日** 的常规工程工作，目前已经完成。

## 总量判断

- **可展示的 AI 全栈 MVP：约 12–18 人日剩余**。可以暂时使用单用户模式，但必须具备真实模型工具调用、基本评测和可访问的部署环境。
- **可公开运营的小型版本：约 29–46 人日剩余**。需要数据库、身份与数据隔离、完整限流、可观测性、备份和发布治理。
- 单人实施时，MVP 通常需要约 3–4 周；公开运营版本通常需要约 6–10 周。多人并行不会按人数线性缩短，因为 API 契约、评测和上线验收存在依赖关系。

## 推荐下一步

下一项变更应实现“AI 策略助手 MVP”：

1. 定义模型 Provider 接口和可注入假实现；
2. 把商品查询、正向计算、反向计算暴露为模型工具；
3. 增加流式助手接口与浏览器对话面板；
4. 强制最终数值引用工具结果；
5. 建立第一批 30 条固定评测场景；
6. 模型不可用时保持现有 Web 计算和 CLI 正常工作。

数据库迁移可以与 AI 接口设计并行准备，但不应阻塞第一版工具调用验证。
