# v0.5.0 — Measurable AI Quality And Resilient Conversation

This Pre-release makes assistant behavior measurable and the browser conversation resilient while preserving the deterministic calculation and evidence boundaries.

## Demonstrable workflows

- Continue a page-local conversation with at most six validated prior messages and force every follow-up calculation or market value through fresh current-turn tools.
- Stop an active assistant request and explicitly retry a failed or cancelled turn without appending calculation history.
- Parse typed OpenAI Responses text and function-call streams while withholding the complete model answer until grounding passes.
- Run 50 deterministic tool cases without provider credentials.
- Run an opt-in 12-case semantic suite against current or retained baseline prompts and compare content-free JSON reports.

## Engineering additions

- Bounded OpenAI SSE parsing for output text, function-call argument deltas, completed responses, provider failures, and malformed or oversized streams.
- Additive `history` request field with strict role, count, per-message, and combined-size validation; the original message-only contract remains valid.
- Prompt `steam-profit-assistant-v1.1.0`, which treats history as untrusted intent context and requires fresh evidence for every current market or calculated number.
- Browser `AbortController` cancellation, accessible Stop and Retry controls, and a six-message in-memory context window.
- Versioned semantic evaluation suite, prompt selector, threshold engine, optional caller-priced cost estimate, and `steam-profit-eval` binary.
- Reports that contain case IDs and execution metadata but omit credentials, prompt text, model prose, arbitrary provider payloads, and tool values.

## Verification

- `make check` passes formatting, JavaScript syntax, `go vet`, race-enabled tests, and all three binaries.
- Exactly 50 deterministic tool cases pass, including success, invalid input, dependency failure, unknown tool, and boundary behavior.
- Scripted evaluation tests cover report success, tool mismatch, aggregate threshold failure, provider failure, native-stream metadata, and content-free output.
- OpenAI adapter tests cover typed streamed function arguments, native text deltas, transient history, JSON fallback, safe provider failures, and grounding-safe release.
- Six Chromium workflows pass, including page-local context/retry and cancellation with unchanged calculation history.
- The OpenSpec change passes strict validation.
- No temporary OpenAI key is available in the local milestone environment, so the opt-in paid current/baseline smoke is documented but not represented as an executed result.

## Compatibility and limitations

- CLI commands, trusted formulas, lookup normalization, CSV schemas, SQLite schema, and existing calculation/history JSON contracts remain compatible.
- Assistant conversations remain page-local and disappear on reload; this is not authenticated or cross-device chat storage.
- Native provider output is safety-buffered until whole-answer grounding completes, so this milestone does not reduce verified-answer first-token latency.
- The default semantic command runs a stable three-case prefix to bound cost; `--max-cases 0` is required for the complete 12-case live suite.
- Model prices are caller-supplied; the repository intentionally contains no hard-coded price table.
- Authentication, quotas, public rate limiting, hosted TLS, managed backups, persistent telemetry, scheduled live evaluation, and PostgreSQL remain future milestones.
