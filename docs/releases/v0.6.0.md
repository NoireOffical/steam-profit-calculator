# v0.6.0 — Controlled Railway Demo And Minimum Safety Boundary

This Pre-release turns the local AI full-stack practice project into a controlled, reproducible online demonstration while preserving deterministic calculation, storage compatibility, and the disabled-by-default model boundary.

## Demonstrable workflows

- Open the Railway HTTPS health endpoint without credentials while keeping the browser workbench and application APIs behind shared reviewer credentials.
- Use the deterministic lookup, calculation, reverse-calculation, and SQLite history workflows under bounded per-client request limits.
- Run scheduled or manual read-only hosted checks without writing records or calling a paid model.
- Write one versioned persistence marker, restart the Railway deployment, and verify that exactly the same marker remains in the attached `/data` volume.
- Export the complete Railway data directory, pass SQLite integrity checking, and boot an isolated restore that can read the pre-restart marker.

## Engineering additions

- Optional constant-time Basic authentication with startup validation and an intentionally public dependency health endpoint.
- Bounded process-local fixed-window API limits, a separate hourly provider-run quota, safe `429` responses, and no-side-effect rejection paths.
- Content-free aggregate counters for unauthorized, rate-limited, and assistant-quota requests.
- A seventh Chromium workflow for public health, rejected credentials, and authenticated browser access.
- Manual-only current/baseline live-model evaluation and a scheduled/manual hosted smoke workflow with injected secrets.
- Railway `PORT` and trusted `X-Real-IP` support, one-replica deployment configuration, HTTPS, secret injection, persistent SQLite storage, health checks, and graceful stop.
- A narrowly scoped Railway volume-permission entrypoint: the image remains non-root by default, repairs only `/data` when explicitly started as root by Railway, then immediately drops to `steam-profit` through `su-exec`.
- A two-phase hosted persistence workflow and a documented manual full-volume export/restore path.

## Compatibility and limitations

- CLI commands, trusted formulas, lookup normalization, CSV schemas, SQLite schema, calculation/history JSON contracts, prompt version, and assistant tool schemas remain compatible.
- Access controls and limits remain disabled by default for local development.
- This is a one-replica reviewer demo, not an account or multi-tenant system. Basic credentials, request limits, quotas, metrics, and SQLite do not provide cross-replica coordination or user isolation.
- Railway Trial managed Backups/PITR require a paid upgrade and were not enabled. The verified recovery evidence is a manual full-volume export and isolated restore, not a managed snapshot or point-in-time recovery.
- The hosted assistant remains disabled. No temporary OpenAI key was supplied, so this milestone contains no paid current/baseline provider report and makes no live-model quality claim.
- Process-local limits and metrics reset on restart; persistent telemetry and alert escalation remain future work.
