# v0.4.0 — Deployable Demo And Browser E2E

This Pre-release turns the local AI full-stack workflow into a repeatable demonstration with real-browser regression coverage, stable seed data, a containerized single-process runtime, dependency-aware health, and content-free aggregate telemetry.

## Demonstrable workflows

- Start an isolated seeded demo and navigate calculation history across stable filters and pages.
- Save a browser calculation, reload the page, and retrieve the same record from SQLite.
- Demonstrate that invalid browser input creates no record and disabled AI does not affect deterministic workflows.
- Run the same embedded application through Docker Compose with a durable named SQLite volume.
- Read health, request correlation IDs, structured request logs, and aggregate runtime metrics.

## Engineering additions

- Four Playwright Chromium E2E workflows with a temporary database and no live provider credentials.
- Versioned 12-row seed dataset generated by the deterministic calculation engine and imported idempotently.
- Multi-stage non-root image, read-only Compose runtime, named volume, health check, and graceful stop.
- Process-local atomic request and assistant counters exposed through `GET /api/v1/metrics`.
- Random request IDs and status-aware JSON logs that omit query strings, headers, bodies, prompts, outputs, and record content.
- Dependency-aware `/api/health` behavior for SQLite and legacy CSV repositories.
- CI gates for Linux Chromium E2E and container restart persistence.

## Verification

- `make check` passes, including formatting, JavaScript syntax, `go vet`, race-enabled tests, and both binaries.
- `pnpm e2e` passes all Chromium scenarios against the real server and SQLite repository.
- The OpenSpec change passes strict validation.
- Focused tests cover concurrent metrics, content-free logging, request IDs, SSE flushing, dependency failure, and health safety.
- Container build, health, seed idempotency, and restart persistence are configured as a required CI gate; this local machine has no Docker runtime, so the remote gate must pass before release.

## Compatibility and limitations

- CLI commands, calculation formulas, CSV schemas, SQLite schema, prompt version, and existing JSON workflows remain compatible.
- Metrics reset on process restart and are intended for demonstrations and local troubleshooting.
- The container is intentionally one application replica backed by SQLite; it is not a multi-user or horizontally scalable deployment.
- The default E2E suite never calls Steam or OpenAI and does not validate live-model semantics.
- Authentication, rate limiting, managed backups, public TLS, persistent telemetry, alerting, and PostgreSQL remain future milestones.
